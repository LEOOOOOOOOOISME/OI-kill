## 一、🔴 严重问题（崩溃 / 内存安全 / 状态损坏）

### BUG-001 装备槽位裸指针悬垂（UB，可崩溃）
- 位置：`game_engine.h:45-48`（`Player::weapon/armor/mount_off/mount_def` 为 `Card*`，指向 `std::vector<Card> equip` 内的元素）；`game_engine.cpp:123-144`（`equipCard`）、733-740（拔网线）、832-843（请家长）、932-947（抄袭代码）、1264-1274（找代打）。
- 问题：`equip` 是 `std::vector`。`push_back` 触发扩容时会使**所有**旧元素指针悬垂；`erase` 会使被删元素及其**之后**元素的指针悬垂。例如装备武器时若 `equip` 扩容，已装备的 `p.armor` 指针指向旧缓冲区 → 之后 `target.armor->name` 为野指针读（UB）。拔网线/请家长删除中间装备后，排在后面的武器/防具指针同样悬垂。
- 影响：随机崩溃、防具/武器效果错乱（如已装备的 AC保护/黑名单突然"失效"或读到垃圾数据）。

### BUG-002 玩家索引越界访问（客户端可崩溃服务器）
- 位置：`game_engine.cpp:56`（`getPlayer` 无边界检查）、`57`（`isAlive` 同）；`useCard` 中爆零(910)、停课集训(903)、压轴题(1161)、代码审计(1293)、女装求AC(1025)、学长讲题(1062)、请家长(830)、TLE/MLE/CE(1085/1093/1102)、玄学优化(1131)、卡评测机(1141)、找代打(1251) 等均直接 `getPlayer(targets[0])`；`performAcAttack:666-668` 对任意 `tgt` 调 `isAlive`。
- 问题：`targets` 来自客户端消息，服务端未做 `0 <= id < players.size()` 校验。恶意/异常客户端可发送 `targets:[999]` 或负数 → `players[999]` 越界访问。
- 影响：服务器崩溃（vector 越界 UB）或读到任意内存。

### BUG-003 阵亡玩家手牌/装备未弃置（卡牌泄漏）
- 位置：`game_engine.cpp:318-322`（阵亡分支只 `alive=false`）。
- 问题：需求 7.1 "阵亡：弃置全部手牌和装备"。实现未清空 `hand/equip`、未把牌放入弃牌堆。
- 影响：卡牌从牌堆系统中永久泄漏（长局牌堆提前耗尽）；死亡玩家的手牌仍可被"树状数组看牌""抄袭代码""女装求AC"等技能访问（这些技能未校验目标存活）。

### BUG-004 开局后玩家退出 → "幽灵玩家"继续参与对局
- 位置：`room_manager.cpp:314-354`（`removePlayer`）。
- 问题：游戏开始（`started=true`）后有人退出，槽位被重置为 `name="等待加入"`、`alive=true` 且**保留身份/职业**，但 `info.started` 仍为 true，新玩家无法加入（addPlayer 拒绝）。该空槽仍会轮到自己回合、摸牌、弃牌、被计入胜利条件，变成自动行动的"幽灵玩家"（15 秒超时自动结算）。
- 影响：对局被幽灵玩家接管，胜负判定、回合轮转、身份阵营全部失真；与需求 7.1 "阵亡退出游戏" 语义不符。

### BUG-005 同一 socket 并发 wsSend 无锁（帧交错）
- 位置：`network_server.cpp:582`（错误消息直接 `wsSend`）、409/424/429/463（顶号/封禁消息）、721（`broadcastToRoomState` 直接 `wsSend`）。
- 问题：`GameSession::mtx` 只在 `broadcastToRoom`/`broadcastToLobby`（660/674）中加锁，其余发送路径不加锁。游戏操作线程（错误响应）与广播线程可同时对同一 socket 写数据。
- 影响：WebSocket 帧交错 → 客户端解析失败、连接异常；属数据竞争（UB）。

### BUG-006 使用被 erase 的引用读取卡牌字段（use-after-free 读）
- 位置：`game_engine.cpp:842`（请家长 `player.evoCandidates.push_back(card.id)`）、950（抄袭代码同）、962（重构同）。
- 问题：这些分支先 `discardFromHand(player, cardIdx)`（从 `player.hand` erase 该卡），随后又通过 `card.id` 读取已被删除的元素（`Card& card = player.hand[cardIdx]` 的引用已失效）。
- 影响：形式上的悬垂引用读取（UB），值可能正确也可能错误；`-O2` 下可能优化出异常行为。

## 二、🟠 规则逻辑错误（明确违背《需求.txt》）

### BUG-101 被【WA】抵消的做法假了不计入出牌次数 → 可无限出杀
- 位置：`game_engine.cpp:695-700` + `processResponse:1735-1807`。
- 问题：需求 4.4/Q3 "每回合默认只能使用 1 张【做法假了】"。实现中只有**命中**才 `acUsedThisTurn++`（716、1724）；目标成功打出 WA 抵消后（1735-1807）**不增加计数**。
- 影响：玩家可反复出【做法假了】被闪避，次数限制完全失效（手牌够就能无限攻击）。

### BUG-102 【玄学判题】在单杀响应中完全失效（判定分支是死代码）
- 位置：`game_engine.cpp:1708-1730, 1736-1746`。
- 问题：`response_wa` 中 `card_index=-1`（玄学判题判定）先被 `if (cardIdx < 0 || waBanned) { finishHit(...); }`（1727）拦截，判定逻辑（1736）**不可达**。
- 影响：装备【玄学判题】的角色被【做法假了】指定时，选择"判定"= 直接放弃闪避 = 必然受伤；八卦阵形同虚设。

### BUG-103 【玄学大师】（进化）的 -1 判定被当作放弃闪避
- 位置：`game_engine.cpp:1708`（`xuanxueJudge` 只认 `"玄学判题"` 不认 `"玄学大师"`）。
- 问题：`-1` 在 1711 行的 `!xuanxueJudge` 条件下被判为"放弃"→ `finishHit`。
- 影响：进化后的玄学大师判定（红桃/方块视为 WA）在单杀响应中同样无法触发。

### BUG-104 判定区多张延时锦囊结算时跳过后续卡牌
- 位置：`game_engine.cpp:2095-2141`（`judgeDelayArea`）。
- 问题：水群/断网分支 `erase` 后落入 for 循环的 `++i`（被删元素后的卡牌前移却被跳过）；UB 爆炸分支同样（只有 UB"传下家"用了 `continue` 是对的）。例：判定区 [水群, 断网] → 结算水群后 i++，断网被跳过，留到下回合。
- 影响：同区多张延时锦囊（如 水群+UB、断网+水群）只结算第一张。

### BUG-105 【UB】传给下家时未检查下家判定区是否已有 UB
- 位置：`game_engine.cpp:2112-2117`。
- 问题：需求 9.3 "下家若已有 UB 则继续传给再下家"。实现直接把 UB 追加进下家 `delayArea`。
- 影响：同一玩家判定区可堆多张 UB（且配合 BUG-104 还会被跳过）。

### BUG-106 【压线过】救援优先级错误（抢在所有救援手段之前）
- 位置：`game_engine.cpp:230-244` vs 需求 7.1（压线过是第 5 位，最后手段）。
- 问题：压线过在伤害生效前拦截（蒟蒻退役/颓废标记/谈心/咖啡之前）。例如"摸鱼怪身份 + 压线选手职业"受到致命伤时，应优先自动消耗颓废标记（第 2 位），实际却被压线过抢先触发（消耗每回合 1 次额度）。
- 影响：救援顺序错乱，压线过次数被无谓消耗。

### BUG-107 【卡线Au】觉醒后体力值计算错误
- 位置：`game_engine.cpp:236-237`。
- 问题：觉醒文案"体力上限 +1 并回复 1 点体力"。压线过把致命伤转为剩 1 血后，觉醒再"回复 1"应为 2 血；实现 `target.hp = std::min(target.max_hp, 1)` 强制为 1。

### BUG-108 【划水怪】"连续 2 回合未造成伤害"计数单位错误

## 三、🔵 安全 / 健壮性问题

### BUG-201 管理接口日志文件路径遍历（任意文件读取）
- 位置：`network_server.cpp:272-278` + `logger.h:73-80`（`dir_ + "\\" + name` 直接拼接）。

### BUG-202 superadmin 防降级保护缺失
- 位置：`auth.h:224-241`（`setRole` 中 `if (newRoleStr != "banneduser" && a->username != "superadmin") {}` 是**空语句**）。
- 问题：注释声称"superadmin 不可被降级"，代码无任何保护；`ban()`（242-258）也不保护 superadmin。

### BUG-203 密码哈希强度弱 + 无登录/注册限速
- 位置：`socket_util.h:110-126`（FNV-1a 迭代 64 次、`genSalt` 用 `rand()`，盐可预测）；`auth.h:135-174`（登录/注册无频率限制）。

- 影响：局域网内可暴力破解/撞库；默认账号 superadmin/admin123 明文打印在启动信息中（main.cpp:72）。
