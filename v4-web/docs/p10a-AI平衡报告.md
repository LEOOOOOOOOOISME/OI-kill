# P10a AI 平衡调参报告（OI杀 v4）

> 执行代理：P10a（AI 统计 + 平衡调参）
> 范围：仅修改 `src/ai/identity-policy.js` / `src/ai/scorer.js` / `src/ai/heuristics.js`（调参级改动，未动引擎/数据/网络/UI/测试）；新增 `test/ai-stats.mjs` 与 `build/` 下诊断脚本。
> 目标（recon-02 §E P3-6 / requirement 20.3）：胜方阵营占比 ≈ **反贼 33% / 主公方 60% / 内奸 7%**，容差 ±8（即 25–41 / 52–68 / 0–15），三难度至少两档达标。
> 口径说明：本报告所有“胜率”均为 **胜方阵营占全部对局的份额**（每局恰有一个胜方阵营，三者之和=100%），非各阵营的独立胜率。

## 一、结论速览（诚实版）

1. **调参方向对、幅度不够**：8 轮迭代把 normal 档从 反贼42.5/主公方30/内奸27.5 拉到 **反贼37.2/主公方37.0/内奸25.8**（500 局），内奸 -1.7、主公方 +7、反贼 -5.3。**反贼已落入容差**，但主公方与内奸离目标仍有结构性缺口。
2. **内奸份额（≈22–26%）被引擎规则钉死，不是 AI 旋钮能解决的**：诊断显示 200 局 normal 中有 37 局进入“主公 vs 内奸”单挑，内奸赢下 **35/37（95%）**，其中 16 局是靠【保底终局】“人数相同→内奸单独获胜”（FAQ#15）的规则判胜；单挑中内奸每回合回 1 体力（H12），而主公的攻击牌密度（约 0.3 张/回合）远低于内奸回血速度，**主公在单挑里数学上无法获胜**——即使入场时血量领先（25/37 局领先，仍输 23 局）。
3. **任务指定的“1 人类挂机”口径无法承载平衡目标**：人类=主公且一切提示超时答“否”、回合只弃牌结束时，主公方胜场仅 2.5–19.5%，反贼 56–86%。该口径下把主公方调到 60% 等于让 AI 反贼输给一个完全不出牌的主公，会摧毁真实单机体验。33/60/7±8 的目标是按 **AI 对 AI** 口径标定的（p3b 的 10 局/档基线就是全 AI 局），故本报告以全 AI 口径为主口径调参，1 人类口径作为附报。
4. **回归全绿**：self-test 62/62、test.js A 40/40 + B 5/5 + C 6/6、test-extra E 34/34、suite-d D 8/8（148 断言）。p3b 记录的三个旧 AI 测试兼容偏差（E25/E33/B102）**未被重新触发**。
5. **最终建议**：要么调整引擎规则（见 §十），要么按 recon-02 “文档先行原则”回写 requirement.txt 20.3 的目标值；单纯 AI 调参无法把内奸压到 ≤15%、主公方抬到 ≥52%。

## 二、度量口径与工具

### 2.1 口径 A：全 AI 局（主口径）
`createGame({seed, human:99, difficulty})` → 6 座全 AI，`drive({thinkMs:0})` 驱动至终局（零人形延迟、零挂起提示）。与 p3b 报告的 10 局/档基线同口径；33/60/7 目标即按此口径标定。

### 2.2 口径 B：1 人类 + 5 AI（任务指定 harness，副口径）
`createGame({seed, humans:[0], difficulty})`（0 号恒为主公）：人类一切挂起提示经 `timeoutPrompt` 秒答“否/放弃”，人类回合仅 `discardPhase+endTurn`（镜像 suite-d D06）。该口径模拟“人类主公完全挂机”的最坏情形，不是平衡目标的有效载体，但按任务要求完整报告。

### 2.3 `test/ai-stats.mjs`（新交付物）
```
node test\ai-stats.mjs [N=200] [difficulty] [--seed base=1] [--quiet] [--no-human]
```
每局统计：胜方阵营、回合数（g.round）、行动轮数（turnsPlayed 合计）、崩溃、非法动作（日志 `[AI] 跳过非法动作`，零容忍）、终局牌张守恒 120（含挂起提示 ctx 中临时持有的展示牌，见 §十一）、终局提示残留（信息项）、drive cap。种子可复现（seed=base+i）。

### 2.4 调参旋钮实际生效面（重要）
- `identity-policy.js` 的 `attackPrio` 系数 / `aggression` / `selfPreserve` / `weights`：**只影响 normal/hard 的选牌打分**（easy 的 `useThreatModel=false` 使动作选择恒为候选内均匀随机，打分只决定候选集）。
- `policy.retention` 字段：**无消费方，改了不生效**（真正生效的是 difficulty 表的 `retentionBias` 与 scorer `keepValue`）。
- `heuristics.js` 的响应/单挑分支：对**三档难度都生效**（身份判定不依赖难度开关）。
- `scorer.js keepValue(coffee)` 内奸倍率：影响弃牌保留与咖啡自留。
- 引擎规则（单挑回血 H12、保底终局 FAQ#15、颓废标记、击杀反贼摸3）：**不可改**（任务约束），恰是内奸份额的决定因素。

## 七、差距与根因（诚实版）

1. **内奸 22–26% vs 目标 ≤15%**：内奸胜局 2/3 来自【保底终局】FAQ#15“人数相同→内奸单独获胜”，1/3 来自单挑磨杀。根因链：内奸单挑每回合回 1（H12）＞主公单挑攻击密度（攻击牌占牌堆 15%，主公约 0.3 次有效攻击/回合）→ 主公永远磨不死内奸 → 对局拖到二次洗牌 → 规则判内奸胜。这是**引擎数值设计**决定的，AI 侧旋钮（少闪/不龟缩/不自保/少杀忠）只把 27.5 压到 ≈23–26。
2. **主公方 33.5–40% vs 目标 ≥52%**：主公方胜局需要“杀光 3 反贼 + 内奸”，而反贼集火窗口开启时主公掉血速度（3 反贼 × 每回合 1 伤 vs 主公 6 血 + 1 盾 + 免伤）远快于主公方清场速度；AI 侧已把忠臣攻击加成抬到 1.15、主公 1.2、残局解除冻结，仍差 12–18 个百分点——缺口主要落在“内奸该赢的局必须转给主公方”，而那条路被规则堵死。
3. **反贼 37.2/41.0（normal/hard 已达标，easy 差 0.5）**：反贼的目标选择被 scorer 的敌意模型主导（主公是唯一确定敌人 h=1.0），策略加成只做 ±2 个百分点的微调；easy 因动作随机选择，策略旋钮基本失效，只能靠 difficulty 表与 heuristics 的身份分支（本次 easy 主公方 48→52 主要来自单挑行为改动）。

## 八、建议的后续工作（按优先级）

1. **引擎规则微调（需主代理/产品裁决，本代理无权限）**：
   - 内奸单挑回血（H12）改为“每 2 回合回 1”或“仅体力 ≤ 上限一半时回 1”；
   - 保底终局 FAQ#15 的 1:1 平票改为“主公方胜”或“继续洗牌再战一轮”；
   - 或：内奸击杀反贼不触发“摸 3 张”奖励（该奖励放大内奸终局滚雪球）。
   预计 (a)+(b) 即可把内奸压到 7–12%、主公方抬到 50%+。
2. **若规则保持不动**：按 recon-02 的“文档先行原则”回写 requirement.txt 20.3，把目标校准为与引擎规则相容的值（例如 反贼 38±8 / 主公方 38±8 / 内奸 24±8，即现状）；否则 60/7 的目标在现规则下不可达。
3. **AI 侧可继续的空间**：normal 档 randomPickPct 0.18→0.3（历史上“随机 AI 主公方 67.5%”，适度随机对主公方有利且更像真人）；easy 档单独调 dodgeHpThreshold/retentionBias 把反贼抬过 25；scorer 反贼对主公的隐式敌意加权（当前 h=1.0 恒最大，可给反贼加“护盾未破/非残血时打折”）。
4. **1 人类口径的 harness 改进**：若要用该口径度量，应给人类座位配“智能自动应答”（用 heuristics.chooseResponse 代答、回合用 chooseAction 打），此时结果 ≈ 全 AI 口径；纯挂机口径只能作为最坏情形回归，不能作为平衡验收。
5. **终局提示残留**：对局在结算中途结束（保底终局/击杀）时，引擎不清理挂起提示组（1 人类口径每 200 局有 4–10 次，全 AI 口径为 0）。建议引擎在 `end()` 时清空 `g.prompts`/`g._promptGroups`（防 UI/服务器层在终局后误渲染），并顺手复核 easy seed 161 的 1 张牌在“特判连锁挂起中触发保底终局”时的去处（见 §十一）。

## 十、附注：守恒口径与两个个案
