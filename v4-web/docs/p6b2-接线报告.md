## 4. promptInfo 归一化

```js
function promptInfo(pd){
  if (!pd) return null;
  if (pd.payload && typeof pd.payload === 'object')      // ① 联网原始信封 {promptId,payload{type…},timeoutMs}
    return { type: pd.payload.type, ctx: pd.payload.ctx, promptId: pd.promptId, pd: pd.payload, timeoutMs: … };
  const pid = pd.promptId != null ? pd.promptId : pd.id != null ? pd.id : null; // ② 联网合并形状(payload+promptId) / ③ 本地引擎条目(promptView, id)
  return { type: pd.type, ctx: pd.ctx, promptId: pid, pd, timeoutMs: null };
}
```

三形状通用：联网提示信封（type 在 payload 内、promptId 顶层）、镜像里存的合并形状（payload 字段平铺 + promptId）、本地引擎条目（type 顶层、id=提示id）。渲染路径直接用 `v.pending`（联网时已被归一为 payload 平铺形状，`pd.type` 顶层可读），应答路径统一经 promptInfo 取 promptId。**冒烟期间抓到并修复一个真实 bug**：初版 promptInfo 只识别信封/引擎两种形状，对镜像合并形状（无 `payload`、无 `id`）返回 promptId=null 导致 net 模式所有应答静默丢失——已修复并由 net 冒烟「dodgeResp(false) → sendResponse(pd-1,{yes:false})」断言锁定。

## 5. 联网模式渲染/提示/计时流

- **state → 镜像 g**：`applyState(m)` 把 `state.view`（即 publicView 形状，render() 原样消费）合并为镜像 `g = {players, turn, round, deck, discard, over, winner, achievements, evoWait, pending}`；players 由 view.me + view.others 拼装（me 带 prof.id 注入以驱动技能区；others 带 prof{name,plain}/units/delayArea 供 seatHtml/killUnit 目标圈）。非视图本地 UI 状态（selected/mode/discardSel/usedLimited 等）不动。
- **prompt → 提示 UI**：定向 `prompt` 信封 → `onPromptMsg`：`g.pending = {...payload, promptId}` + 重置 shownPromptKey → render() 走既有 `renderPendingPrompt` 的 `payload.type` 分派（dodge/counter/weapon/aoe/report/harvest 弹窗原样复用）；`evo` 走 renderEvoPrompt，`discard`（引擎暂不产生，防御分支）进入弃牌选择模式。pending 合并规则：状态视图 pendingView 作首发/回退（含 id=promptId）；并发多槽时保留我的定向提示；view.pending 为空 ⇔ 全部提示已解决 → 清空；应答 ack（ref=promptId）即时清 pending。
- **event**：gameover → 结算弹窗（gameOverShown 去重 + stopTimers）；shutdown → toast(原因) + 禁用「结束出牌/自动托管」；log/turn 事件暂不额外处理（render 已从视图 log 全量渲染），fx/sfx 挂载点留给 P7。
- **setup**：`HUMAN = setup.pid`（座位打乱后未必 0，全局 `let HUMAN` 重指）+ 存 NET.setup/身份/座位表 + 隐藏大厅；首个 state 就绪后弹「🎮 开局」身份弹窗（重洗按钮经 `lordRedraw` 动作，服务器侧校验主公）。
- **reject**：net → `toast('被拒绝: why')`；本地仍走各调用点原弹窗（无回归）。
- **计时**：本地沿用旧 45s/10s 本地计时；net 用服务器权威截止——回合 `NET.turnDeadline = now + state.deadline.turn`（仅 my turn 的 turnKey 首次出现时重置，与服务器 startTurnTimer 对齐）、响应 `NET.promptDeadline = now + prompt.timeoutMs`；环形倒计时/超时自动结束回合/超时自动"否"全部复用原组件（onTurnTimeout→endPlayFlow→C.endTurn；onRespTimeout→respondNo→C.sendResponse）。
- **大厅**：lan 模式挂 `#page-lobby` 覆盖层（新增 `.lobby-*` CSS 与 lobby.js 类名一一对应），`mountLobby(el, C, {url, name:'你', onGameStart: hideLobby})`；本地模式保留原人数选择弹窗（net 模式下「重开/再来一局」toast 提示由房主控制）。join 前先挂大厅再自动 join：大厅自己的订阅先于 hello，入座/座位列表/房主控件由 lobby.js 自维护，避免预 join 后二次点击造成双座位。

## 7. 务实决策汇总

1. **/api/hello 无 mode**：探活即联网，lan/single 由 join 的 hello.mode 判定（偏差记录）。
2. **lan 先挂大厅再自动 join**：避免"预 join 后用户再点加入"造成双座位/旧 promise 覆盖误判。
3. **本地模式整体经 LocalClient 驱动**（任务指定 "C is LocalClient"）：本地 AI 泵接管旧 runAi 循环；玩家名变为 AI-2..AI-N（适配层设计，人数弹窗文案已同步），thinkMs:0 保证 AI 决策/节奏与旧版一致。
4. **自动托管语义收敛**：两模式统一为"提示默认是/首张、evo 取首个、我的回合自动结束"（旧本地版由 aiTurn 代打手牌，与门面泵双驱动会竞态，已删 runAi/aiRespondPending）。
5. **ai 脚本加载命名空间观察**：任务指定顺序（game.js 之后）下，浏览器端 ai 模块挂在被 game.js 重赋值的扁平 api 的 `OIKill.ai` 上；引擎内部捕获的是重赋值前的共享命名空间，因此浏览器本地 AI 维持 P6b 之前的旧启发回落路径（= 零回归），heuristics 完整生效于 Node 服务器侧（require 路径）。若未来需要浏览器端启用启发式 AI，应把 ai 四个脚本移到 game.js **之前**加载——此点已记录供后续阶段决策。
6. **观战（lan spectate）**：只渲染公开视图，动作会被服务器 reject → toast；未做专门观战 UI（任务未要求）。
7. **evo/discard 语义提示**：evo 走提示信封路径（本地/联网统一），discard 保留防御分支（当前引擎不产生该提示）。
